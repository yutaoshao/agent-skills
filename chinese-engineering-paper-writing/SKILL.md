# 中文工程论文写作

把研究中最值得发表、且有证据支撑的价值写清楚。以“问题为什么成立、方法具体改了什么、实验回答了什么”为主线，让章节相互推进，不把算法名称、实施步骤和图表数量当作贡献。

本技能提炼自 25 篇中文机器人论文分析形成的独立写作指南。完整章节卡保存在 [references/writing-guide.md](references/writing-guide.md)，无需访问原始语料、其他 skill 或历史对话。范文模式是组织参考，不是期刊规则，也不提供目标研究的事实。

## 按请求确定范围

- 起草：依据研究材料产出所请求的章节或全文；关键事实缺失时具体指出，能写的部分继续写。
- 重写或优化：先识别原稿的研究主张和证据，再调整组织、段落功能与表达；保留真实方法、数据、引用归属及数学含义。
- 评审或建议：给出具体问题和可替换文字；只有用户要求修改文件时才写入原稿。

单节任务只读取指南中的相关章节卡及所需上下文；全文任务读取完整指南。不要为了写一个摘要启动整套论文工程，也不要自动要求重新拆解参考论文。

普通起草、重写和润色使用下述主流程。逐句评审、期刊核对和文档保护按后文“按需能力”选择，不把所有检查加载成默认流水线。用户已授权的重写可以调整段落、合并重复内容和重新安排强调位置，只需保护事实与证据关系，不为这些常规编辑重复请求批准。

## 先确定论文要证明什么

阅读指南的“先选择论文主线”和“写作前材料单”，将现有材料收束成一句话：

> 在〔对象与条件〕下，针对〔具体困难〕，通过〔核心机制〕实现〔任务改善〕，由〔关键实验〕支持。

选择与研究实质相符的主线：算法改进、学习映射、候选生成与精修、多解或多目标选择、机构或控制系统。组合方法要确定主次，不能仅因组件共存就把每个组件都列为创新。

建立简短的“具体问题 → 实际措施 → 对应证据 → 可支持的结论”映射。用于指导写作即可，不必把工作表塞进论文或每次都作为交付物。只有映射改变结构、暴露关键缺口或需要用户判断时才展开说明。

若是综述，改用“综述问题 → 检索范围与分类依据 → 文献证据 → 比较结论”，跳过不适用的方法与新实验要求。

缺失且影响主要主张的材料，提出具体问题；仍需输出时使用 `〔待补充：具体材料及用途〕`。不以笼统的“效果较好”填补事实空白，不把缺失信息改成自己的方法设计。

## 用章节卡写出论证

依据 [写作指南](references/writing-guide.md) 中相应卡片的目标、材料、步骤、条件和检查执行，不只套用骨架句式。

- **题目、摘要、引言**：题目突出实际贡献；摘要压缩问题、核心动作、验证范围与代表性结果；引言按问题分类文献，对最近邻方法说明保留了什么、改变了什么以及原因，末段使问题、措施和验证对应。
- **问题、模型、数据**：先定义任务输入与可接受输出，再说明坐标、约束、度量和数据形成方式；区分主任务与次目标、标签与输入、训练与测试职责。
- **方法、参数、流程**：先给完整数据流，再按“原问题 → 新动作 → 计算定义 → 输出作用”解释模块。说明改动位置、参数控制的行为、接口依赖、预算与终止后的返回对象，基础理论只保留定位改动所需内容。
- **实验、结果**：每组实验回答一个贡献问题。按研究选择“优化器到任务”“模块到整体”或“模型到实体”的展示路径；交代公共条件、对照、成本与统计层级。结果段先给发现和关键证据，再解释与机制的关系，不逐图复述。
- **公式、图表、引用**：说明材料为何出现及后续用途；公式解释符号与计算角色，图表提炼发现，引用落实到所支持的事实或方法归属。
- **结论**：回应引言中的问题，回收主要机制贡献和已证发现，条件放在相关结论处；确有明确后续才写展望，不重复实验流水账。

全文可按“问题与证据映射 → 图表与实验问题 → 任务与方法 → 结果 → 引言与结论 → 摘要与题目”起草；这是起草建议，不是必须呈现给读者的章节顺序。不固定句数、段数、贡献数或小节数。

## 让表达力度与证据对应

贡献应明确、集中，不平均展示所有工作，也不用反复自我限制冲淡发现。将真实适用条件放在读者解释结论所需的位置。

- 范文只迁移组织与表达，不迁移创新、数值、结论或未核实引用；不补造消融、硬件、能耗或泛化实验。
- 整体效果不能分配成每个模块的独立贡献；无对应对照时用设计目的或与观察一致的解释，不伪装成因果证明。
- 区分单次最优与重复统计、目标数量与随机重复次数；保留均值、RMSE、P95 等原始定义、聚合顺序和单位。
- 仿真残差、实体测量和代理指标分别命名；迭代次数不直接等于耗时，角位移不直接等于能耗，随机波动不直接等于外界扰动鲁棒性。
- 保留影响核心结论的差异结果，准确说明优势集中在哪里，不把每项指标都写为领先。

修改已有稿件时读取 [事实与数学保护](references/integrity-boundaries.md)，按所改范围核对数字、引用、公式和关键命题；这是编辑底线，不要求每次建立全文逐句账目。

## 按需能力

| 请求或材料 | 读取与执行 |
| --- | --- |
| 中文表达、术语、衔接或去机械感 | [中文表达](references/chinese-academic-style.md)：在句段语境中处理，不按禁词表替换 |
| 逐句审查、内容取舍或深度编辑 | [逐句功能审查](references/sentence-function-audit.md)：覆盖约定范围，判断保留、改写、合并、移动、删除或待确认；完整对照报告仅在用户要求时交付 |
| 含公式、数学符号或公式引用的 DOCX 修改 | [Word 公式保护](references/word-equation-typesetting.md)：修改前后结构审计，保留 OMML/OLE 和字段，最终文档逐页核对；普通文字重写不触发公式必要性的全文审查 |
| 中文核心、CSCD 等目标期刊规范核对 | [期刊规则记录](references/journal-profile-schema.md)：查验目标期刊当期官方要求；未知期刊不阻止一般写作 |
| 全文深度评审、正式交付检查 | [评审检查](references/review-checklist.md)：只运行适用项，不将写作审查称为实验复现或录用保证 |

配套脚本路径相对本技能目录，输入文件路径由当前任务提供：

```bash
python3 scripts/check_chinese_style.py manuscript.md --json
python3 scripts/audit_word_equations.py manuscript.docx
python3 scripts/audit_word_equations.py before.docx --compare revised.docx --strict
```

中文风格脚本只支持 UTF-8 文本、Markdown 或 LaTeX，报告诊断提示而不改写；DOCX/PDF 应先按格式提取文本。公式审计不能证明数学正确或视觉排版正常。

## 完成交付

按指南“全文一致性检查”核对问题与贡献、贡献与机制、机制与实验、结果与结论、数据职责、物理与代理、图表与文字、文献归属。对单节任务核对相关链路即可。

优先交付可直接使用的正文，随后简要说明关键组织调整及具体未解决项；只有用户要求时才提供完整逐句对照报告。不要用写作计划或检查清单替代正文。

若修改 DOCX、LaTeX 或其他源稿，保留可编辑公式、图表和引用结构，并使用当前环境适用的文档工具核对受影响内容与渲染结果。没有执行的排版检查、实验复现或期刊核验不能报告为已完成。
